**Round-2 audit batch B: cross-account isolation, locking, and escaping.**
The second-correctness audit found five stores keyed by too little, one lock
bug, and two XML escape gaps. All land here:

- **Cross-account state bleed** — Log metric/subscription filter stores
  (`filters.py`), SESv2 email templates, X-Ray encryption config and resource
  policies, and SQS's behavioral cooldowns were all keyed by region (or, worse,
  bare queue name). Account A's filter destinations, template HTML, KMS key
  IDs, policy names, and delete/purge cooldowns leaked into account B's
  requests in the same region. Every store now keys `(account_id, region)`
  (plus queue name), matching the in-process contract AGENTS.md documents and
  the sibling stores X-Ray/ECS/SNS/SQS already used.
- **`ReadWriteLock._acquire_write`** only waited for readers — a second
  writer sailed through and two "exclusive" writers interleaved their state
  snapshot pauses. The wait loop now also checks a writer is already active,
  with a test that drives two writers through the save path concurrently.
- **Route 53 `TestDNSAnswer`, `CreateQueryLoggingConfig` and the
  NoSuchHostedZone error** escaped XML for the first time; entities in
  record names and ARNs now parse cleanly client-side.

**Verification choices**: the store-key fixes keep the in-memory snapshot and
restore paths intact (SQS behavioral state snapshots keep their per-key
mapping, and the rwlock test runs a real two-writer race with both writers
