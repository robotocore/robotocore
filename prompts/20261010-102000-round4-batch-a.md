## Key decisions

**Round-4 audit produced 10 live-verified findings; this batch lands the eight
high-impact ones.**

- **moto Lambda backends vanish on every save** — `LambdaStorage._arns` is a
  `weakref.WeakValueDictionary`, whose closures cannot pickle; the save loop
  skipped the whole `lambda` service while metadata.json still claimed it.
  The thread-safe pickler now reduces WeakValueDictionaries to a snapshot of
  live entries and rebuilds them on load (moto's `_functions` strong dict
  keeps the objects referenced, so the rebuild survives GC).
- ** Assumed-role sessions under ENFORCE_IAM implicit-denied** — no handler
  registered the minted ASIA key with the role. `AssumeRole` (forwarded to
  moto) now parses the response XML, canonicalizes the assumed-role session
  ARN (`arn:aws:sts::acct:assumed-role/X/sess` →
  `arn:aws:iam::acct:role/X`) and registers it with the IAM middleware;
  the SAML path registers its minted key the same way.
- **IAM SocialLock XML**: AccessDenied 403 XML escapes the caller-controlled
  action (the same escape class as #360); `aws:CurrentTime` policy context
  evaluates against wall clock instead of a 2024 constant.
- **S3**: notification `object.size` reads the stored object from the moto
  backend (moto's PUT response strips Content-Length, so every
  ObjectCreated reported size 0); all six sub-resource config handlers now
  answer 404 `NoSuchBucket` for buckets the store does not hold (previously
  accepted and leaked across accounts); the website 404/NoSuchKey bodies
  XML-escape the decoded key and the redirect Location header latin-1-fences
  non-ASCII keys.
- **Persistence reach**: boot's state component registers S3 sub-resource
  stores (CORS, lifecycle, transition-min-size, object-lock, legal-hold,
  logging, directory buckets) and the Lambda ESM + function-URL stores using
  the established esk export/load contract; previously only sqs/events/ec2
  were hooked, so every other native store silently died with the server.

**Conclusion tests warning**: unit tests for `aws:CurrentTime` and the sts
registration are new; the S3 deep tests gained a real moto bucket attachment
because the round-4NoSuchBucket guard is now honest about bucket existence
(the old tests attached configs to buckets that had never been created — the
exact defect class under fix).

**Deliberately deferred**: `SNAPSHOT_SAVE/LOAD_STRATEGY` dead wiring
(strategy aside, the "on_request"/"scheduled" strategies are unwired inside
the request path) is a design decision now — the alternatives are wiring the
scheduler into the boot component or striking the docstring. Logged for the
next round rather than guessed.
