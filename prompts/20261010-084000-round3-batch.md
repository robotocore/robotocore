## Key decisions

**Round-3 audit batch: seven more isolation/perf-class defects.** The third
adversarial pass found the same store-scoping class in providers the previous
round's sweep did not cover, plus two escape/lock bugs:

- **Kinesis** `GetRecords` resolved the region store with no account, so
  callers in a second account could not read their own streams (or read a
  same-named default-account stream). The shard-iterator token now carries the
  creating account so the read-back stays account-scoped, and the store is
  resolved for the caller.
- **Step Functions** SQS/SNS integrations resolved the default account's
  store; the state machine's own `account_id` is now threaded in, matching the
  sibling Lambda integration.
- **Lambda event source mappings**: list spilled every account's mapping
  UUIDs (andArn fields) and get/update/delete had no ownership check — any
  account could mutate or delete another's mapping by uuid. All four CRUD
  paths now enforce the (account, region, uuid) ownership the create path
  records.
- **CloudFormation XML**: dict_to_xml emitted scalars verbatim (user tag
  values, parameters) and the error message interpolation too; escaped like
  the other services, plus two ElementTree-namespace-aware round-trip tests.
- **Firehose**: the flusher wrote through the DEFAULT account's S3 backend
  and cleared each buffer before the (possibly failing) put — records
  vanished silently for non-default accounts. Now the stream's own account is
  used and the buffer clears only after a successful write.
- **EventBridge** connections/api-destinations/endpoints leaked across
  regions of one account; keyed (account, region, name) with list filters
  matching, and the state snapshot format gains the region in each key
  (schema_version 2, with the loader accepting old v1 keys by reading the
  region out of the entity ARN — no in-flight 2 undo).
- **Rekognition**: single re-entrant lock around face-collection iteration vs
  delete (finding: concurrent DeleteFaces + SearchFaces could mutate the dict
  mid-iteration and 500 both callers). Deliberately NOT changed: tags keyed by
  ARN (ARN includes the owning account) and video/liveness UUID identities
  are server-generated, so cross-account reads require the caller's own
  resource already — the reachability analysis showed the isolation risk is
  negligible against adding speculative key changes everywhere.

**Test discipline**: new discriminating tests for Kinesis (iterator must
carry account + cross-account read must not resolve) and CloudFormation
entity-escaping; five existing lambda-ESM tests were re-seeded to the caller
account so they now assert the ownership contract, and the firehose tests use
the new `_write_to_s3` account + success-return semantics. Whole
tests/unit/services suite: 6150 passed.
